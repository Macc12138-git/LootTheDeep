# LootTheDeep：区域容器管理与爆率配置开发方案 V0.1

- 状态：经用户授权，已接入首版区域管理、配置窗口与随机掉落；实际行为、验证及边界见[使用说明](RegionContainerLootUsage.md)。
- 设计依据：[设计理念与接续指南](DesignPrinciples.md)、[物资与掉落概念方案 V0.1](LootAndDropConcept-v0.1.md)。
- 主题衔接（2026-10-16）：当前整体基线为[游戏概念 V0.3](GameConcept-v0.3.md)。区域容器与掉落配置继续作为专题方案，既有接入记录不代表新的 Tilemap 世界探索地图已经实现。
- 玩法边界：本工具只配置容器物资，不定义遭遇密度、战斗门槛或撤离条件。容器和特殊目标的奖励配置应服务可选搜索路线，不应要求玩家清空战斗区域。
- 用户提出的需求：区域内容器集中管理；点击区域容器爆率控制后，可查看容器位置、爆率、类型等信息；支持筛选、多选及单个容器配置。
- 下文的组件拆分、配置优先级、界面和开发阶段为建议实施方案；示例数值仅用于说明界面，不替代物资概念方案中的测试参数。

## 一、整体方案

采用 **区域容器管理器＋可视化配置窗口**。

在场景中选择区域，点击“区域容器爆率控制”，集中查看该区域的容器，在列表与场景之间定位，并进行筛选、批量修改和单独配置。

本方案主要管理容器内物品的掉落规则。容器出现概率、每局数量及随机生成点属于后续区域生成配置，不与箱内掉落概率混为一项。掉落配置本身也不决定相关区域是否必须战斗、能否绕行或是否允许撤离。

## 二、区域入口与归属

建议场景层级：

```text
探索地图
├─ 机械维修区（区域容器管理器）
│  ├─ 维修箱 A
│  ├─ 维修箱 B
│  └─ 储物柜 A
└─ 电力控制区（区域容器管理器）
   ├─ 维修箱 C
   └─ 电气柜 A
```

区域管理器的 Inspector 提供：

- 区域名称。
- 区域默认掉落配置。
- 区域内容器数量。
- **打开区域容器爆率控制**按钮。
- 刷新容器列表按钮。

点击按钮后打开编辑窗口，默认只显示该区域的容器。第一版按层级归属收集容器；遇到嵌套区域时，以最近的区域管理器为准，避免重复管理。

采用上方筛选、中间列表、右侧详情，以及 Scene 视图定位的布局。

```text

✓  | 维修箱 A | 维修箱 | (12,-4,0)  | 区域默认 | 机械物资 | 10%
✓  | 维修箱 B | 维修箱 | (18,-6,0)  | 单独配置 | 高级维修 | 25%
   | 储物柜 A | 储物柜 | (21,-3,0)  | 类型默认 | 生活物资 | 3%

右侧详情：
```

表内数值仅作示意。“稀有及以上”需注明为每次抽取口径；多抽取组容器应显示核心奖励、附加奖励等分组信息，不能压成一个含义不明的爆率。

## 四、容器位置与场景联动

| 方式 | 行为 |
| --- | --- |
| 列表定位 | 显示世界坐标和场景层级路径；双击行，在 Scene 视图聚焦该容器 |
| 场景标记 | 对当前区域的容器绘制图标和名称；选中容器显示高亮轮廓 |

标记可按容器类型使用不同图标，单独配置的容器增加一个小标识。提供“仅显示筛选结果”和“仅显示已选容器”选项，避免场景标记过密。

点击场景标记时，同步选中窗口对应行，方便从地图反查配置。

## 五、配置优先级

**容器单独配置 → 区域内该类型配置 → 容器预制体默认配置。**

| 容器 | 类型 | 区域默认规则 | 单独配置 | 最终生效 |
| --- | --- | --- | --- | --- |
| 维修箱 A | 维修箱 | 机械维修表 | 无 | 机械维修表 |
| 维修箱 B | 维修箱 | 机械维修表 | 高级维修表 | 高级维修表 |
| 医疗柜 A | 医疗柜 | 未配置 | 无 | 预制体默认医疗表 |

每个容器详情直接显示：

- 当前最终使用的掉落表。
- 来自哪一级配置。
- 可点击定位到对应配置资源的入口。

查看一个箱子时，不需要手工追查多层引用。

## 六、区域默认与批量配置

| 操作 | 影响范围 | 后续新增容器 |
| --- | --- | --- |
| 修改区域内某类型默认规则 | 该区域内，继承默认规则的同类型容器 | 自动使用新规则 |
| 给选中容器批量指定规则 | 仅当前选中的容器，形成单独配置 | 不受影响 |
| 清除选中容器的单独配置 | 选中容器恢复继承 | 不受影响 |

例如，提高整个机械区维修箱的收益，应修改区域默认规则；让门后三个箱子收益更高，应选中三个箱子批量指定高级规则。

筛选结果和选中集合分别显示数量。**批量操作只作用于明确选中的容器**，不会因为临时改变筛选条件而悄悄扩大范围。

## 七、单个容器配置

选中一个容器后，可选择：

- 继承区域配置。
- 指定已有掉落表 SO。
- 从当前规则创建独立副本并指定。

第三种适合“这个箱子基本相同，但电路板更多”的需求：

1. 点击“创建独立副本”。
2. 从当前生效规则复制一份新的掉落表 SO。
3. 自动指定给该容器。
4. 在右侧面板修改副本。

界面区分“编辑共享规则”和“创建独立副本”。编辑共享 SO 时，面板显示本次扫描范围内的使用容器数量，避免误以为只修改一个箱子。该数量不冒充全项目引用总数。

## 八、爆率展示与预览口径

| 信息 | 显示位置 | 含义 |
| --- | --- | --- |
| 抽取份数 | 列表、详情 | 每箱生成多少次抽取 |
| 品质概率 | 列表摘要、详情 | 每次抽取落入各品质的概率 |
| 物品权重 | 详情 | 同品质候选池内的相对权重 |
| 物品单次概率 | 详情 | 品质概率 × 该品质内物品概率 |
| 整箱至少获得一次的概率 | 预览面板 | 根据份数分布、重复规则等计算或模拟 |

例如“稀有10%”标注为每次抽取，不能直接显示成“这个箱子出稀有概率10%”。

高价值容器示例：

```text
核心奖励：1份，稀有90%，珍稀10%
附加奖励：1—2份，使用附加奖励分布
```

抽样预览使用独立随机状态，不改变场景里的真实容器物品。模拟结果标注样本数，不能冒充理论概率。

## 九、数据结构与项目衔接

以下名称为建议命名。

| 对象 | 职责 |
| --- | --- |
| 现有 `LootDefinition` | 保存物品定义，继续复用 |
| 新增 `LootTableSO` | 保存抽取组、品质权重、候选物品与份数规则 |
| 新增 `RegionLootConfigSO` | 保存区域内“容器类型 → 默认掉落表”的映射 |
| 新增区域管理组件 | 标识区域、收集容器、提供编辑窗口入口 |
| 现有 `SearchableContainer` 扩展 | 增加容器类型、默认表、可选的单独配置 |
| 新增编辑窗口 | 列表、筛选、定位、配置编辑及预览 |
| 新增规则解析与生成逻辑 | 解析最终掉落表，生成独立的容器物品 |

区域管理器负责汇总和协调；每个容器仍持有自己的运行时物品、揭示状态和搜索进度，SO 只保存规则。

本轮讨论时的静态源码检查显示：项目通过 `InventorySession.Containers` 手工维护可交互容器，`SearchableContainer` 使用固定初始物品，搜索过程逐件揭示已有物品。实施前需复核源码现状，不能将此记录作为运行验证。

实施时建议让交互会话使用区域管理器汇总的容器，避免新增一个箱子还要登记两遍。随机生成器以后可通过同一入口注册容器。

## 十、开发阶段与验收

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| 第一阶段：集中查看 | 区域收集、容器列表、筛选、多选、场景定位 | 区域内每个容器能被准确找到，归属不重复 |
| 第二阶段：配置管理 | 掉落表、三级优先级、单独配置、批量指定、恢复继承 | 界面显示的最终规则正确，保存重开后保持一致，操作支持 Undo |
| 第三阶段：掉落接入 | 随机生成、格子摆放、抽样预览、配置检查 | 容器独立生成，反复打开不重抽，核心奖励不因放不下被静默丢弃 |

首轮验收使用两个区域、三种容器类型，再加入一个单独配置的特殊箱子。

重点验证：**区域统一调整能够批量生效，特殊箱子保留独立规则，而且在窗口里能一眼看出两者的区别。**

本方案不预设存读档、堆叠数量、完整随机地图及撤离结算已经实现；相应行为仍需在各自系统中设计和验证。
