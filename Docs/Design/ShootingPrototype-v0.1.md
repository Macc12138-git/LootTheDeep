# Loot The Deep：射击靶场原型方案 V0.1

- 整理日期：2026-10-09。
- 状态：首版靶场原型已于 2026-10-10 接入工程；测试参数仍非最终平衡，运行验收见文末。
- 后续阶段：换弹与局内战斗原型见 [CombatPrototype-v0.1.md](CombatPrototype-v0.1.md)；本篇的测试弹药与“暂不做换弹”仅描述靶场初版。
- 设计依据：[设计理念与接续指南](DesignPrinciples.md)、[游戏概念方案 V0.2](GameConcept-v0.2.md)。
- 本轮目标：只验证潜艇移动时的鼠标瞄准、当前武器显示、两武器切换、实体弹丸和静止靶子的命中反馈。

## 一、已明确范围与待确认事项

用户已明确：先做射击逻辑，不做敌人；在场景中放几个靶子；鼠标瞄准位置需要可见准心；需要明确 `Player` 预制体上的当前武器和武器方向如何随鼠标变化。本方案保留已有水下移动，采用独立的靶场验证，不把这一步当作完整战斗或搜打撤闭环。

原话中的“潜艇的主武器和服务器”含义尚未确认。此前讨论暂将后者理解为“副武器”；下文以 `SecondaryWeapon` 作临时代号，仅表示第二个可切换的射击槽位，**不确认其是手持武器，也不涉及网络服务器**。武器外形、装配位置和正式名称待确认。

暂不做敌人 AI、追击或反击、噪声传播、战斗掉落、武器升级、换弹、背包弹药、出入潜艇、撤离及结算。当前项目的水面基地与水下行动仍是独立场景，潜艇不因本原型成为随时可用的安全出口。

## 二、当前工程与目标改动

实施前 `Assets/Prefabs/Gameplay/Player.prefab` 只有 `PlayerInput`、`UnderwaterMover2D` 和 `Visual/Body`、`Visual/FacingMarker`。`UnderwaterMover2D` 根据水平移动翻转 `Visual`，所以新武器节点挂在独立的 `CombatRoot` 下。输入配置原有 `Attack` 的鼠标左键绑定和 `Previous`/`Next` 的 `1`/`2` 绑定；新加的 `AimPoint` 读取 `<Mouse>/position`，原有 `Look` 的 `<Pointer>/delta` 不作为准心坐标。`InventorySession` 打开背包时会停止移动并显示系统光标，射击与准心在 UI 状态停用。

已接入的预制体和场景层级如下：

```text
ExploreScene
├── Gameplay
│   ├── Player.prefab
│   │   ├── Visual                         现有；仅保留移动方向的外观翻转
│   │   │   ├── Body
│   │   │   └── FacingMarker
│   │   └── CombatRoot                     新增；不跟随 Visual 翻转
│   │       └── WeaponPivot                新增；随鼠标方向旋转
│   │           ├── MainWeapon             新增；可见外形与 Muzzle
│   │           └── SecondaryWeapon        新增；可见外形与 Muzzle
│   ├── Target_Close                       新增；静止靶
│   ├── Target_Middle                      新增；静止靶
│   └── Target_Far                         新增；静止靶
└── Canvas
    ├── Crosshair                          新增；屏幕空间准心
    └── CombatHUD                          新增；当前武器名称与测试弹药
```

同一时刻只显示选中的武器及其炮口。按 `1` 选择主武器、按 `2` 选择第二武器，显示对象和 HUD 同步变化；未选中的武器既不显示也不射击。准心不随武器切换而跳动。`WeaponPivot` 和两个 `Muzzle` 以局部正 X 为射击轴，炮口放在该轴上，使视觉朝向与正常距离的发射方向一致。准心取代上一版方案中的世界空间 `AimTargetMarker`；额外瞄准线不作为首版必需 UI，避免遮挡场景。

## 三、操作与可视反馈

| 操作 | 原型输入 | 反馈 |
| --- | --- | --- |
| 移动 | 现有 `WASD` / 方向键 | 潜艇移动；外观可按移动方向翻转 |
| 瞄准 | 鼠标屏幕位置 | 准心跟随鼠标，当前武器朝对应世界位置旋转 |
| 射击 | 按住鼠标左键 | 按当前武器射击间隔发射，炮口闪光和弹丸可见 |
| 主武器 | `1` | 仅显示主武器，HUD 更新 |
| 第二武器 | `2` | 仅显示第二武器，HUD 更新 |

准心采用清晰但不遮挡靶子的简洁像素图形，锚点位于鼠标坐标。只在可射击的游戏画面中隐藏系统鼠标并显示准心；打开背包、搜索 UI、窗口失焦或离开靶场时恢复系统光标，隐藏准心并阻止射击。返回游戏时重新读取鼠标位置。准心表达“想瞄的位置”，不承诺移动目标必定命中，也不包含自动锁定。

## 四、瞄准与射击的一致性

鼠标使用**屏幕绝对位置**，经当前正交摄像机转换为 2D 游戏平面上的世界位置；不能把 `<Pointer>/delta` 当作目标位置，也不能把 UI 坐标直接用作弹道方向。

```text
每帧：
    鼠标屏幕坐标 = AimPoint 读取的 <Mouse>/position
    Crosshair 屏幕位置 = 鼠标屏幕坐标
    瞄准世界点 = 当前摄像机的屏幕射线与 2D 游戏平面求交

    pivotDirection = 瞄准世界点 - WeaponPivot 世界位置
    如果长度足够大：
        WeaponPivot 旋转到 pivotDirection
    否则：
        保持上次有效朝向
```

开火时从**当前武器**的 `Muzzle` 世界位置生成弹丸。由于武器、炮口沿 `WeaponPivot` 的正 X 轴布置，在准心位于炮口前方且超过最小瞄准距离时，炮口、准心和弹丸初始轨迹应共线。弹丸方向由发射时的 `瞄准世界点 - 当前 Muzzle 世界位置` 计算，随后锁定方向，不在飞行过程中追踪准心。准心位于炮口以内或背后时不允许开火，并用准心弱化状态提示无效瞄准；不要悄悄向其他方向发射。近距离阈值在场景中按实际炮口偏移调试。

这套约束避免了“武器看向一个方向，弹丸却从潜艇中心或另一把武器射出”的错位。潜艇的移动外观翻转只影响 `Visual`，不能改变 `CombatRoot` 的瞄准轴。武器贴图若在瞄准左侧时倒置，可仅翻转贴图子节点；`WeaponPivot`、`Muzzle` 和弹道方向不翻转。

## 五、武器与靶子的测试数据

下表仅供首轮对比手感，不是正式平衡，也不接入背包：

| 参数 | 主武器 | 第二武器 |
| --- | ---: | ---: |
| 单发伤害 | 30 | 8 |
| 射击间隔 | 0.7 秒 | 0.15 秒 |
| 初始测试弹药 | 6 | 24 |
| 弹丸速度 | 中等 | 较快 |
| 命中表现 | 明显的重击反馈 | 较轻的连续受击反馈 |

每把武器独立保存当前弹药和下次可射击时间。可提供仅用于靶场的“无限弹药”调试开关；关闭后弹药耗尽无法继续射击。本版没有 `R` 换弹，重载场景恢复初始弹药。弹丸带有伤害、速度、最长存活时间和所有者；与自己及自己的发射器不碰撞，命中靶子扣血，命中阻挡物或超时则消失。快速弹丸应使用可靠的 2D 连续碰撞检测，避免穿透薄靶子。

三个靶子固定在不同距离，不主动移动或攻击。各有生命值、碰撞体、受击闪烁/颜色变化和可见生命条；生命归零后禁用碰撞并隐藏或播放击毁效果，重载场景复原。可暂用近靶 30、中靶 60、远靶 100 生命值检查两武器的命中和伤害差异。靶子不掉落物品。

## 六、模块与伪代码

```text
PlayerAimController:
    读取 AimPoint 的鼠标绝对坐标
    更新屏幕空间 Crosshair
    转成 2D 世界瞄准点并旋转 WeaponPivot
    判断当前 Muzzle 到准心的有效射击范围
    UI 打开/失焦时停用射击准心，恢复系统光标

PlayerWeaponController:
    维护 MainWeapon、SecondaryWeapon、activeWeaponIndex
    按 1/2 切换显示对象、当前 Muzzle 和 HUD
    如果游戏输入有效且 Attack 按住：TryFire()

TryFire():
    如果 UI 打开、瞄准无效、冷却未结束或测试弹药为空：返回
    origin = activeWeapon.Muzzle.position
    direction = Normalize(aimWorldPoint - origin)
    在 origin 创建当前武器的 Projectile，并传入 direction/damage/speed/owner
    扣除本武器测试弹药（无限弹药模式除外）
    设置本武器下次可发射时间；更新 HUD；播放枪口反馈

Projectile:
    沿发射时固定方向前进，直到碰撞或超时
    碰到 owner：忽略
    首次碰到 TargetDummy：TakeDamage(damage)，播放命中反馈后销毁
    碰到环境阻挡物：播放撞击反馈后销毁
    保证同一弹丸只结算一次命中

TargetDummy.TakeDamage(amount):
    如果已击毁：返回
    扣血、刷新生命条、播放受击反馈
    如果生命值 <= 0：禁用碰撞并播放击毁表现
```

## 七、实施顺序与验收

1. 在输入配置中补充鼠标绝对位置 `AimPoint`；沿用现有 `Attack` 与 `1`/`2` 绑定，接入 UI 打开状态。
2. 调整 `Player.prefab`，添加独立 `CombatRoot`、两把可辨识的测试武器及各自 `Muzzle`；实现当前武器切换和 HUD。
3. 在 Canvas 添加准心，统一实现鼠标屏幕位置到世界点的瞄准、近距离无效状态和光标切换。
4. 实现武器冷却、测试弹药、实体弹丸与环境碰撞。
5. 在 `ExploreScene` 放置三个静止靶子并加入受击/击毁反馈；只在确认不干扰现有容器与背包时保存场景。

验收时逐项检查：`1/2` 的可见武器与 HUD 一致；鼠标移动、镜头跟随及潜艇向左/右移动时准心和武器方向正确；弹丸仅从当前 `Muzzle` 发出并沿准心方向飞行；三种距离的靶子只在实际命中时扣血；弹药耗尽、冷却期间、瞄准无效和 UI 打开时不会发射；重载场景恢复测试弹药与靶子。此原型通过只代表射击链路和手感可验证，不代表敌人、战斗经济或完整搜打撤已实现。

## 八、实施与验证记录

- 运行逻辑：`PlayerShooter2D`、`ShootingProjectile2D`、`TargetDummy2D`、`ShootingHud2D`；输入增加 `AimPoint`。`ShootingRangeInstaller` 用于生成预制体和场景节点，重复运行不会重复创建靶子与 HUD。
- 资源：`Player.prefab` 增加两把可见武器、各自的 `Muzzle` 和短暂闪光节点；`MainShot.prefab`、`SecondaryShot.prefab`、`TargetDummy.prefab` 为原型资源；三个靶子和屏幕空间 HUD 已保存到 `ExploreScene`。
- 在同版本 Unity 6.3 的隔离工程副本中，安装和引用校验通过；Play Mode 验证了主武器弹丸击毁近靶、第二武器弹丸对中靶只造成一次 8 点伤害，以及控制器开火扣弹、点亮当前炮口闪光并击中远靶。HUD、背包仍可加载。批处理日志另有 Unity 自带 SearchDatabase 的索引异常，不在本功能调用栈。鼠标真实手感、可视表现和原工作区编辑器的导入状态仍需在编辑器 Game 视图人工确认。
