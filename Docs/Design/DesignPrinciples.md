## 一句话理解

**在俯视角像素世界中探索、搜索与承担风险，通过有效撤离带回物资，建设长期保留的基地，再为下一次行动准备；地图使用 Unity Tilemap 制作。**

## 用户明确的方向

1. 2D 像素风。
2. 纯单机，不包含联机内容。
3. 探索主题调整为较为开放的世界探索，游戏玩法继续采用搜打撤。
4. 探索采用俯视角，地图使用 Unity Tilemap 制作。
5. 长期养成采用基地建设，基地同样使用俯视角。

继续沿用的方向：

- 基地与探索区域分离，每次外出是一局独立行动；世界连接方式后续仍可讨论。
- 每局包含随机出生地、随机物资、随机高价值容器和随机撤离点。
- 搜到物资不等于永久获得，成功撤离后才进入基地仓库。
- 敌对人类由 AI 驱动；其他敌人种类按新世界观设计。
- 保存概念、实现功能与生成图片分别按用户当次要求执行。

## 为什么调整到 V0.3

用户将主题从水下探索改为较为开放的世界探索，并明确探索与基地建设都采用俯视角、地图使用 Tilemap 制作。本轮调整使主题、视角、地图方案与基地成长方向保持一致。

V0.3 延续此前确立的搜打撤结构：

- **局外与局内分离**：基地保留长期资产，外出探索承载单局风险与收益。
- **行动局势随机**：入场位置、资源、高价值目标及有效出口共同改变路线。
- **收益必须撤出**：搜到、放入背包与正式入库是不同状态。
- **撤离是决策与行动**：抵达有效出口并满足条件，才能完成本局结算。
- **建设产生探索需求**：基地需要的材料影响本局目标，局内收获又影响建设与下一局配装。

“较为开放”当前按单局区域内自由探索、多路线与自主目标选择设计。世界是否无缝连通、多个探索区域如何连接及跨区域结算方式仍待确认；开放程度的调整需要保留有效撤离与资产结算边界。

## 玩法参考：动作反馈与搜打撤决策并重

用户提出参考《元气骑士》的玩法。本项目借鉴其直观战斗反馈、可读的攻击节奏、武器差异和多样遭遇，不照搬视角、关卡通关结构或具体数值。凉屋[官方介绍](https://www.chillyroom.com/zh/game-news/2/8)提到躲避攻击、收集武器、角色技能差异与随机地牢；页面同时描述了横版表现，与本项目已明确的俯视角不同。关卡房间类别可参考[社区维基整理](https://yqqs.huijiwiki.com/wiki/%E5%85%B3%E5%8D%A1%E6%A8%A1%E5%BC%8F)，该来源为非官方且可能随版本变化。

当前采用的转译原则：

- **战斗短促、反馈清楚**：敌人的攻击起手、方向或危险范围应可读；玩家可以走位、借助掩体、反击或脱离，不把承伤硬拼作为唯一解。
- **遭遇有变化，但路线不被锁死**：战斗点、补给点、搜索点和高价值目标形成节奏差异；普通战斗点和高威胁目标原则上可绕过，不因清空区域才开放道路或撤离。
- **战斗胜利不等于行动完成**：精英敌人或首领式目标可以作为可选风险峰值，提供额外收益，但击败它不自动结束本局、不替玩家触发撤离。
- **局内变化服从撤离规则**：可拾取武器或战术强化目前只是设计候选；若采用，应改变本局打法而非直接形成永久能力。任何作为战利品带回基地的装备仍须成功撤离。
- **奖励避免逼迫清图**：战斗掉落补充搜索；容器与区域目标仍是建设材料的主要来源，避战路线也应能推进基础成长。

这些是当前设计方向，不等于已确认控制方式、敌人种类、首领系统、武器槽位或临时强化系统。

潜水器、氧气、艇体耐久、变异鱼和海洋灾变背景属于旧主题讨论，不再作为当前默认要求。V0.2 和旧原型保留为历史参考。

## 当前方案采用的理念

以下是 V0.3 的设计基线与玩法参考方向；其中具体规则仍可在后续讨论中调整。

### 搜、打、撤必须互相影响

- 搜：搜索和开启容器需要时间，可能制造噪声；携带空间使不同物资产生取舍。
- 打：战斗产生暴露、伤害、装备损耗与行动时间成本，也可能获得敌人携带物资；允许绕行和避战。新的角色战斗、武器和弹药规则待设计，旧潜艇原型的有限弹匣、无限备弹不自动成为新规则。
- 撤：根据战利品、玩家状态、出口位置与条件决定何时停止搜索，把局内收获转为局外资产。

### 战斗遭遇服务于路线选择

- 敌人攻击应提供可识别的预警和躲避机会，战斗空间要能读出掩体、通路和退路。
- 地图可安排战斗热点、补给、搜索和高价值目标等不同遭遇；它们组织节奏，不组成必须逐个清空的封闭通关房间。
- 交战、绕行、潜行或撤退都应是有效选择。可选高威胁目标奖励额外收益，但不锁住撤离，也不以击败目标自动结束行动。
- 局内拾取和强化若被采用，优先作为本局的临时战术变化；局外永久成长主要由成功撤出的物资和基地建设承接。

### 随机用于改变计划，不用于制造无解局面

- 安全合理的候选出生位置，不直接生成必死开局。
- 本局至少有一个玩家有条件抵达并使用的撤离点。
- 本局出口确定后保持稳定，不无提示地随机消失。
- 高价值容器的位置与内容具有不确定性，不固定沿同一路线领取最高收益。
- 四种随机要素不等于整张地图必须完全程序生成。

### Tilemap 服务于路线与目标设计

- 探索与基地建设均采用俯视角，地图使用 Unity Tilemap 制作。
- 当前建议手工制作地图骨架，再随机配置局内物资、高价值容器和有效出口。
- 地标、道路与区域主题帮助玩家认识地图，多条路线支持搜索、战斗和绕行。
- 地图规模、分区、拼接及程序生成比例仍待确认。

### 基地与探索形成双向推动

- 基地提供配装、补给、仓储、制造和建设目标。
- 战利品价值既取决于稀有度，也取决于玩家当前的建设需求。
- 成长优先增加探索与配装选择，不只提高伤害和血量。
- 生存压力用于产生行动目标，不让反复处理生理指标掩盖搜打撤。

### 失败有代价，但不抹掉整个家

V0.3 暂沿用损失本次携带的可丢失装备和未撤出战利品、保留基地仓库与长期解锁的建议，并提供低成本恢复行动的途径。装备保护、回收方式和死亡惩罚仍待详细确认；背包原型中的保险箱布局不代表保护规则已定案。

## 建议方向，不是用户已经定案的规则

| 事项 | V0.3 当前建议 | 后续需要确认 |
| --- | --- | --- |
| 世界背景 | 林地、聚落、工业区与遗迹作为探索示例 | 世界观、美术主题及首张地图内容 |
| 开放程度 | 单局内自由探索，基地与探索区域分离 | 是否无缝连通、区域连接及跨区域结算 |
| 地图组织 | 使用 Tilemap，手工地图骨架配合局内要素随机化 | 地图规模、分区、拼接与程序生成比例 |
| 出口情报 | 入场提供基础方向，其余线索局内发现 | 精确显示、探索发现或混合方式 |
| 撤离形式 | 区域边界、设施出口、呼叫接应等候选形式 | 首版实际采用的类型与条件 |
| 基地设施 | 仓储、工作台、维修、电力与生产、行动准备等 | 建造方式、占地、配方和成长节奏 |
| 玩家与战斗 | 依据俯视角路线、掩体和退路设计交战与避战 | 控制实体、移动、武器、弹药及操作方式 |
| 动作遭遇 | 参考清晰反馈、可读攻击和多样遭遇；战斗点可绕过 | 攻击预警、闪避/移动操作、遭遇密度、临时武器或强化 |
| 失败损失 | 局内投入有损失，局外长期资产保留 | 具体可丢失物品与恢复机制 |
| 生存消耗 | 随行动和生产推进，不做离线持续消耗 | 指标种类与消耗节奏 |

单局时长、时间压力、正式背包规则、经济数值、存读档及随机种子持久化均未定案，不应在实现时默认已有结论。物资方案中的概率、容器数量和成长节奏需结合新地图重新验证。

## 首轮验证范围

建议先验证：一处俯视角基地、一张 Tilemap 探索地图、四种随机机制，以及完整的准备、入场、搜索、可选战斗或避战、自主撤离、入库和建设闭环。地图至少能让玩家选择高风险目标或绕行路线；不要用强制清房代替搜打撤决策。

暂不扩展复杂居民管理、大规模基地攻防、自动化工厂或庞大的任务阵营系统。联机内容明确不在项目方向内。

旧主题原型的实现和验证记录保留，具体状态以工程与专题说明为准。更新概念文档不代表俯视角世界探索、Tilemap 地图或基地建设已经实现。
