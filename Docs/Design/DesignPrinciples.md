# LootTheDeep：设计理念与接续指南

- 记录日期：2026-09-09
- 当前概念基线：[游戏概念方案 V0.2](GameConcept-v0.2.md)
- 用途：供新加入项目的人或另一台机器上的 Codex 快速理解设计方向。
- 阶段：概念设计；暂不生成概念图，不代表任何玩法已实现。

## 一句话理解

**在水面建设长期保留的家，在独立水下场景中进行随机化搜打撤；带装备入场，搜索并承担风险，从有效撤离点带回物资，再投入基地建设与下一次行动。**

## 用户明确的方向

1. 2D 像素风。
2. 纯单机，不包含联机内容。
3. 玩家通过操作潜水器或亲自潜水探索海底，搜索可用物资。
4. 利用带回的资源建设水面基地并生存。
5. 海底存在变异鱼类和攻击玩家的敌对人类；在单机前提下，人类敌人由 AI 驱动。
6. 水面建造和下水探索是两个独立、不连续的场景。
7. 每局包含随机出生地、随机物资、随机高价值容器和随机撤离点。
8. 当前先保存和完善文字概念方案，不先出概念图。

## 为什么从 V0.1 改为 V0.2

V0.1 偏向开放海域探索与生存建设：玩家从基地连续下潜、采集，再沿途返航。用户指出，这没有充分融合搜打撤。

V0.2 的关键修正不是增加几种随机掉落，而是改变游戏结构：

- **局外与局内分离**：基地保留长期资产，水下行动承载单局风险与收益。
- **行动局势随机**：入场位置、资源、高价值目标及有效出口共同改变路线。
- **收益必须撤出**：搜到、放入背包与正式入库是不同状态。
- **撤离是决策与行动**：不能随时点击返回基地，也不能默认回到潜水器就安全结算。
- **建设产生探索需求**：基地需要的材料影响本局目标，局内收获又影响建设与下一局配装。

不要在后续设计中退回“连续开放海域＋随时回家存物资”的结构。

## 当前方案采用的理念

以下是 V0.2 的设计基线；其中具体规则仍可在后续讨论中调整。

### 搜、打、撤必须互相影响

- 搜：搜索和开启容器需要时间，可能制造噪声；携带空间使不同物资产生取舍。
- 打：战斗消耗补给、产生暴露，也可能获得敌人携带物资；允许绕行和避战。
- 撤：根据战利品、玩家状态、出口位置与条件决定何时停止搜索，把局内收获转为局外资产。

### 随机用于改变计划，不用于制造无解局面

- 安全合理的候选出生位置，不直接生成必死开局。
- 本局至少有一个玩家有条件抵达并使用的撤离点。
- 本局出口确定后保持稳定，不无提示地随机消失。
- 高价值容器的位置与内容具有不确定性，不固定沿同一路线领取最高收益。
- 四种随机要素不等于整张地图必须完全程序生成。

### 基地与探索形成双向推动

- 基地提供配装、补给、仓储、制造和建设目标。
- 战利品价值既取决于稀有度，也取决于玩家当前的建设需求。
- 成长优先增加探索与配装选择，不只提高伤害和血量。
- 生存压力用于产生行动目标，不让反复处理生理指标掩盖搜打撤。

### 失败有代价，但不抹掉整个家

V0.2 建议损失本次携带的可丢失装备和未撤出的战利品，保留基地、仓库与长期解锁，并提供低成本恢复出航的途径。装备保护、潜水器损失、回收方式和死亡惩罚仍待详细确认。

## 建议方向，不是用户已经定案的规则

| 事项 | V0.2 建议 | 后续需要确认 |
| --- | --- | --- |
| 画面视角 | 优先考虑横向侧视 | 横向侧视还是其他 2D 视角 |
| 世界背景 | 海洋灾变后的拾荒生存 | 世界观及叙事规模 |
| 地图组织 | 稳定地标配合局内要素随机化 | 地图结构的随机程度 |
| 出口情报 | 入场提供基础方向，其余线索局内发现 | 精确显示、探索发现或混合方式 |
| 撤离形式 | 基础、条件、呼叫等候选类型 | 首版实际采用的类型与条件 |
| 潜水器 | 入场运输、局内载具或特定撤离方式 | 是否可驾驶、操作切换及损失规则 |
| 失败损失 | 局内投入有损失，局外长期资产保留 | 具体可丢失物品与恢复机制 |
| 生存消耗 | 随行动和生产推进，不做离线持续消耗 | 指标种类与消耗节奏 |

单局时长、氧气与时间限制的关系、战斗操作、背包形式、经济数值、存读档及随机种子持久化均未定案，不应在实现时默认已有结论。

## 首轮验证范围

建议先验证：一座基地、一张海域地图、四种随机机制，以及完整的入场、搜索、战斗或避战、撤离、结算和建设闭环。

暂不扩展复杂居民管理、大规模基地攻防、自动化工厂或庞大的任务阵营系统。联机内容明确不在项目方向内。

## 交给另一个 Codex 的接续说明

在新的项目对话中可直接说明：

> 请先阅读根目录 AGENTS.md、Docs/Design/DesignPrinciples.md 和 Docs/Design/GameConcept-v0.2.md。以 V0.2 的独立局内搜打撤加局外水面建设为基线，区分已明确方向与待确认建议，不退回连续开放海域采集玩法。先检查项目实际状态，不把概念文档当作已实现功能，也不要未经要求开始写代码或生成图片。
